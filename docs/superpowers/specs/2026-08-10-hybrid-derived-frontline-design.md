# 史料錨點與單位推導混合戰線設計

日期：2026-08-10

## 目標

讓陸戰戰線在來源支持的離散快照之間自然、連續地變化，同時維持史實與 renderer 推導的明確界線。

- 史料戰線仍是指定時間點的最高優先錨點。
- 兩個錨點之間由當下作戰單位位置生成低信心推導戰線。
- 推導結果只存在於 app，不寫回歷史 JSON，也不宣稱為來源支持的史實。
- 到達史料錨點時，混合戰線必須完全等於該錨點。
- 不建立火力、兵力、補給、士氣或地形通行模型。

## 資料責任

同一份 schema 0.4.0 JSON 保留兩類來源資料：

- `frontline_snapshots`：來源直接支持的特定時間戰線或控制區。
- `actors` 與 `movements`：來源支持或有限推定的作戰單位代表位置及移動。

不新增 schema 欄位。推導戰線是 renderer 狀態，不得序列化到 JSON。

AI 只負責史料整理：

1. 來源明確記載的單位、時間、位置、行動與戰線可以直接整理。
2. 只有來源已確認單位由 A 地移動到 B 地及其先後關係時，才可建立代表性 movement；使用 `precision: "inferred"`、`confidence <= 0.5`。
3. 不得從單位點位、勝負、傷亡、突破或包圍敘述生成 `frontline_snapshots`。
4. 不得為動畫平滑新增虛構單位、事件、時間點或路徑轉折。
5. `frontline_snapshots` 必須有直接支持該時間與大致形狀的地圖來源。資料員依該圖概括幾何時可標 `inferred`，但不能以低信心包裝無來源的線條。

## 顯示模式

單一 Fronts 按鈕依序循環四種模式：

1. `hybrid`：預設。史料錨點之間使用單位推導，並逐漸收斂至下一個錨點。
2. `source`：只顯示既有史料快照插值。
3. `derived`：只顯示依當下單位位置生成的戰線。
4. `off`：隱藏所有戰線。

模式只改變顯示，不改變 JSON、單位位置或時間軸。舊文件的可讀性不變。

Inspector 顯示當下 provenance：

- `SOURCE-BACKED`
- `HYBRID · 推導 NN% / 史料校正 NN%`
- `DERIVED FROM UNIT POSITIONS · LOW CONFIDENCE`
- `單位資料不足，使用史料補間`

## 推導戰線

### 單位選擇

納入有當下位置的陸上 `army`、`corps`、`division`、`brigade`、`regiment`。`unit` 只有能由結構化資料可靠判定為陸上單位時才納入；不以名稱猜測。

同一指揮樹中若父級與子級同時有位置，只使用當下有位置的最細葉節點，避免同一兵力重複影響戰線。海軍、空軍與 person 排除。

第一版只在當下恰有兩個具合格陸上單位的 side 時生成推導線。多於兩方的接觸邊界需要額外的分區及標示規則，先回報 unavailable，不任意合併陣營。

### 影響場

在由戰役資料界定、且不隨 pan/zoom 改變的地理範圍建立固定低解析度網格。每個網格點分別計算至雙方最近合格單位的距離，雙方距離差形成標量場；零等值線代表推定接觸邊界。

- 使用 marching squares 抽取零等值線。
- 對結果做少量、確定性的折線平滑。
- 移除距離任何有效敵我單位都超過接觸門檻的線段，避免跨越大片無人區。
- 不按 `strength` 加權；來源間的兵力數字通常不可直接比較。
- 固定 `precision: inferred`、`confidence: 0.35`，只供顯示。
- 不增加外部依賴。

網格尺寸、平滑次數與接觸門檻是 renderer 常數，不進 schema。只有實測品質或效能不足時才增加設定。

### 時間連續性

推導器每次使用 timeline 已插值的當下 actor positions，因此單位連續移動時，影響場也連續更新。相同輸入必須得到相同輸出；seek 與倒退播放不能依賴前一幀的可變狀態。

## Hybrid 收斂

相鄰史料錨點之間先計算當下推導戰線，再依歷史進度增加下一錨點的校正權重：

- 前段以推導線為主。
- 越接近下一錨點，史料校正比例越高。
- 在錨點時間，結果完全等於史料幾何。

相容的開放線或閉合線先重新取樣、方向與起點對齊，再做幾何混合。分裂、合併、線段數不同或開放／閉合拓撲不同時，不強行扭曲；使用局部 crossfade，閉合形成可沿用既有 enclosure reveal。scrub、程式化 seek 與 `prefers-reduced-motion: reduce` 直接顯示確定結果，不補播轉場。

若某時段無法形成有效推導戰線：

- `hybrid` 退回兩個史料錨點之間的既有插值，並在 inspector 說明。
- `derived` 不畫戰線，顯示單位資料不足。
- 只有一個史料錨點時，維持該錨點，不外推未有證據的歷史變化。

## Prompt 1.2.0

README 提示詞升為 `Battle JSON Prompt 1.2.0`：

- `schema_version` 維持 `"0.4.0"`。
- `metadata.source_system` 固定為 `"battle_json_prompt_1.2.0"`。
- 要求來源允許時採師／旅級 actors，提供能表達關鍵階段的代表位置、movements 與 waypoint times。
- 強調同一單位跨階段使用穩定 actor ID。
- 同時保留來源直接支持的 `frontline_snapshots`，不得因 app 能推導戰線而省略史料。
- 明確禁止 AI 將單位推導結果寫成 `frontline_snapshots`。
- 範例改為多個敵我陸上單位與至少兩個分階段位置，示範資料粒度而非暗示虛構細節。

Prompt 不要求每個單位都有 movement；缺少來源支持時必須省略，而不是補齊一條看似完整的戰線。

## 錯誤處理

- 無合法 actor positions、不是恰好兩個有效陸上 sides，或抽取不到有效邊界時，推導結果為 unavailable，不中止其餘動畫。
- 非有限座標、無法解析的 parent reference 或不合法 movement 仍由既有 validator 阻止。
- 某條混合幾何無法安全對應時只對該線 crossfade，不讓整個 renderer 失敗。
- 模式切換清除尚未完成的戰線 transition，並立即以當下時間重繪。
- 載入新文件時預設回 `hybrid`；若只有一種戰線能力，按鈕仍保留四態語意，但不可用模式顯示明確 unavailable 狀態，不暗中改寫使用者選擇。

## 測試

最小必要測試涵蓋：

- 單位移動時推導邊界連續且結果確定。
- 局部推進只改變鄰近戰線。
- 突出部與閉合包圍可由測試點位形成。
- 父子 actor 不重複計算。
- 單方、稀疏與過遠單位回傳 unavailable。
- hybrid 在錨點時間完全等於 source snapshot。
- 推導不足時 hybrid 使用史料插值 fallback。
- source、derived、hybrid、off 模式切換與 inspector provenance 正確。
- seek、倒退與 reduced motion 不播放殘留 transition。
- schema 0.1.0 至 0.4.0 舊文件保持相容。
- README Prompt 版本、固定字串、證據界線與多單位範例受到契約測試保護。

## 參考範例

實作完成後新增突出部之役範例。優先使用 1944-12-16、12-20、12-25 的來源支持戰線與師級部署，保留兩者以驗證：

- source 模式能重現史料錨點。
- derived 模式能從單位位置生成獨立低信心戰線。
- hybrid 模式能在錨點間自然變化並準確收斂。

範例仍以來源粒度為上限；若無法可靠定位某師或某時段，不為了演算法測試而虛構座標。

## 非目標

- 不把推導戰線寫回 JSON。
- 不修改 schema 0.4.0。
- 不建立兵棋模擬、戰力權重或控制區預測。
- 不從道路、現代國界或地形推算戰線。
- 不保證每場戰役都能由稀疏單位資料生成完整戰線。
